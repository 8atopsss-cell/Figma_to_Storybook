# Автоматическая регистрация сравнения Figma

Панель «Figma: изменения» показывает только компонент выбранной истории Storybook. Playground, Light, Dark и Docs связываются с родительским component entry через индекс Storybook. Похожие имена, префиксы ID и внешние Storybook references не используются для сопоставления. Подключение bridge общее; данные сравнения, действия и ошибки относятся к выбранному компоненту.

## Добавление компонента

Отдельно настраивать его сравнение не требуется. Обычный экспорт должен сохранить исходные данные и происхождение:

1. React-компонент и `.stories.tsx` со статическими `title`, `component` и optional `id`.
2. Исходный экспорт `source/figma/<component-kebab-name>-export.json`, например `alert-export.json` для Alert.
3. Полные исходные COMPONENT_SET или COMPONENT деревья с native IDs. Поддерживаются отдельные `light`/`dark`, `trees`, `sets`, массивы наборов и одиночные `tree`/`set`. Презентационные frames не дублируют уже найденные корни. Дополнительные icon/group корни относятся к тому же компоненту.
4. Проверенный `source.fileKey` и `source.fileName`, когда ключ доступен. `sync-project.json` один раз задаёт явный общий файл для legacy-экспортов без fileKey; имя файла само по себе не подтверждает идентичность. Экспорт другого файла без ключа остаётся неподключённым.

Реестр `source/figma/component-links.json` и компактный индекс `.storybook/figma-sync/source-context.json` генерируются автоматически при старте/сборке Storybook. В dev-режиме наблюдатель обновляет их при добавлении, изменении или удалении модулей и экспортов. Bridge перечитывает реестр; панель получает актуальные привязки из API, поэтому новый компонент не требует ручного изменения manager addon. Для отдельного запуска доступен `npm run figma:sync-registry`.

`legacyExports` нужен только для прежних нестандартных имён, например `fresh-export.json` у Button. Для новых компонентов действует общее соглашение об имени исходного файла. Сгенерированный реестр не редактируется вручную. Исходные экспорты, Figma definitions, пользовательские исключения и derived-правила не подменяются генератором.

При отсутствии или некорректности источника компонент попадает в `unconfigured` с причиной; панель сообщает, что сравнение не настроено, и не показывает чужие изменения. Ошибка одного экспорта не назначает ему выдуманные узлы или baseline.

## Первая база и последующие изменения

Регистрация сразу даёт доступ к сравнению, но не доказывает, что текущий React-код совпадает с Figma. Первое сравнение показывает предварительную разницу с историческим экспортом. После переноса и проверки точного снимка реализация регистрируется через `mark_storybook_implemented`; пользовательский OK назначает визуальную приёмку. При дальнейших изменениях Figma новая разница считается относительно этой проверенной базы.

Для legacy-плагина без fileKey подтверждение файла проверяет корни выбранного компонента. Проблемный источник другого компонента не блокирует эту операцию. Новая версия bridge поддерживает отдельные COMPONENT roots, несколько источников одной темы и вложенные пути исторических деревьев.

Общая проверка ревизии кода пока консервативна: изменения проекта могут потребовать повторной проверки реализации других компонентов. Граф зависимостей для точечного определения влияния остаётся отдельной задачей. Автоматическая регистрация не назначает визуальную приёмку и не редактирует Figma.
