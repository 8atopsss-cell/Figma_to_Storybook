# Clean export instructions

## Автоматическая связь с Figma

- Общая конфигурация источника: `source/figma/sync-project.json`. Для каждого нового экспортируемого компонента сохранять исходные деревья в `source/figma/<component-kebab-name>-export.json`, включая `source.fileKey` и `source.fileName`, когда ключ доступен. Статические `title`, `component` и optional `id` в CSF определяют Storybook-привязку; отдельная ручная настройка сравнения не нужна.
- `component-links.json` и `.storybook/figma-sync/source-context.json` генерируются общим механизмом при старте/сборке Storybook и обновляются при изменении исходных экспортов и модулей. После экспорта проверить `npm run figma:sync-registry`; не редактировать сгенерированный реестр вручную.
- Появление компонента в реестре не подтверждает перенос или визуальную приёмку. Регистрация проверенной базы реализации выполняется через bridge после переноса точного снимка; OK назначает только пользователь.

## Симметрия элементов между темами

- Решение пользователя от 6 октября 2026: если у одного компонента есть отдельные light/dark версии и в соответствующем варианте одной темы отсутствует элемент, присутствующий в другой, всегда добавлять этот элемент в реализацию второй темы. Это постоянное разрешение на такие дополнения при работе над компонентом; повторное согласование самого дополнения не требуется.
- Сопоставлять варианты по назначению и состоянию, а не только по порядку или похожему имени. Сначала переиспользовать существующий компонент элемента (например, Badge) с нужной темой. Геометрию и позицию при отсутствии источника брать из соответствующей версии другой темы; оформление — из существующего компонента нужной темы или её явных style IDs. Не подбирать aliases по совпадению цвета и не угадывать неизвестные визуальные значения.
- Дополнение помечать derived/user-authorized, записывать источник геометрии, компонент/токены оформления и исходные IDs. Сохранять исходные raw exports и Figma definitions без подмены; не выдавать добавленный элемент за найденный в Figma. Это правило реализации, само по себе оно не разрешает редактировать существующие компоненты в Figma.
- Правило касается недостающих вложенных элементов в соответствующих вариантах. Оно не создаёт автоматически новые состояния, размеры или все комбинации вариантов. Явные исключения пользователя, например удалённый icon или исключённый expanded, сохраняют приоритет.
