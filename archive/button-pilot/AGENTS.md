# Project instructions

- Read docs/component-contracts.md, docs/component-registry.md and docs/design-system-rules.md before component changes.
- Scope: Button first, IconButton after its contract. Input and Card deferred.
- React + TypeScript + CSS Modules. No additional styling system.
- Canonical tokens: src/tokens/buttons.json. Run npm run tokens; do not hand-edit generated CSS.
- Preserve source node mapping; mark inferred values and missing Figma data explicitly.
- Use semantic HTML, native keyboard behavior and real CSS hover/active/focus-visible.
- Run npm test, npm run typecheck, npm run lint, npm run build, npm run build-storybook and relevant browser checks.
- A passing browser suite does not clear recorded color-contrast debt. Inspect artifacts/browser/a11y-*.json.
- Only user can assign visual acceptance. Do not mark a component accepted based on build or screenshot alone.

## Полнота данных Figma — обязательные правила

- Перед переносом проверить подключённый MCP и фактический состав его ответов. Название инструмента и успешный ответ не подтверждают получение полной спецификации.
- Для каждого компонента читать основной компонент и слои, которые задают его внешний вид. Отсутствие радиуса у component set или группы ничего не говорит о радиусе вложенного фона.
- До реализации собрать применимые параметры: размеры и sizing, Auto Layout, padding и gap; cornerRadius либо четыре отдельных радиуса, corner smoothing; fills и их opacity; strokes, толщину и расположение границы; effects; видимость и opacity слоёв; шрифт, начертание, размер, lineHeight, letterSpacing и textCase; ресурсы, варианты, состояния, темы и связи с токенами.
- Явно различать «получено 0», «поле отсутствует», «смешанные значения», «не применимо к этому типу узла» и «ответ обрезан». Отсутствующее поле считается неизвестным. Не заменять его на 0, none, transparent, браузерное значение по умолчанию или догадку.
- Для обрезанного ответа читать точные узлы, использовать пагинацию и сверять полноту дочерних слоёв. Если инструмент не сериализует нужное поле, увеличение depth/limit и повтор того же запроса не решают проблему: нужен другой доступный инструмент, структурированная выгрузка параметров или значение от пользователя.
- Скриншоты использовать для визуальной проверки и поиска расхождений. Не определять по ним недостающие радиусы, отступы, границы, параметры текста или поведения без отдельного согласования с пользователем.
- Для каждого значения, определяющего внешний вид, фиксировать происхождение: файл, node ID, исходное поле и полученное значение; либо конкретное решение пользователя. Алиасы, созданные в коде, не выдавать за связи переменных Figma. Координаты слоёв не считать доказательством Auto Layout или его отступов.
- Не заполнять публичные токены и финальные стили неподтверждёнными значениями. Существенный неизвестный параметр записать в docs/component-registry.md и остановить только зависимую часть реализации; независимую работу можно продолжать.
- Общее одобрение плана или контракта не считать согласием на неуказанные предположения. Если нужен временный ресурс или реконструкция свойства, сначала явно назвать значение, причину и отличие от подтверждённого источника, затем получить отдельное согласование.
- Перед визуальной приёмкой сверить параметры Figma со стилями и токенами для нужных вариантов и состояний. Тесты, сборка и скриншоты не подтверждают полноту параметров. Неразрешённые пробелы перечислить в отчёте и не назначать статус «принят».
