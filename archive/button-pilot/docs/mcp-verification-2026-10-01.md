### Воспроизводимые сбои

1. `get_node_tree({nodeId: "4391:92046", depth: 0})` возвращает `isError: true`, текст `FIGMA_API_ERROR`. Повтор с depth 3 также завершается ошибкой. Тот же результат для light tertiary `4391:92076` и disabled danger `4391:92061` при depth 0.
2. `get_node_tree({nodeId: "4391:92045", depth: 0})` возвращает set с 48 детьми и warning `component property definitions unavailable`; definitions отсутствуют. Depth 1, limit 100 возвращает `FIGMA_API_ERROR`; отдельная страница offset 1, limit 1 тоже падает. Увеличение лимитов здесь не решает проблему.
3. Прямой `get_node_tree` для `I4391:92047;1900:44734` и `get_node_svg` для `I4391:92047;1900:44734;1893:44709` / `I1900:44762;1900:44734;1893:44709` возвращают `FIGMA_API_ERROR`. При этом dark primary читается с depth 3 и содержит вложенные узлы, а SVG целого компонента работает. Значит, получение дерева через родителя и прямая адресация вложенного ID дают разные результаты. Исходный вектор экспортируется с fill `#9DA4B2`; он не заменяет подтверждение переопределённого цвета экземпляра.

Точный источник этих API-исключений не установлен. `src/plugin/main.ts` заменяет неизвестное исключение на `FIGMA_API_ERROR`, не передавая его сообщение/стек. `readDesignProperties` читает getters без обработки ошибки отдельного поля; это диагностическая уязвимость, но конкретный падающий getter этим аудитом не доказан. Нельзя утверждать, что проблема в радиусах, в схемах или в формате ID, без исходного сообщения ошибки из Figma.

### Проверки кода и границы подтверждения

- `npm.cmd test`: 12 файлов, 51 тест — успешно.
- `npm.cmd run typecheck`: оба TypeScript проекта — успешно.
- `npm.cmd run build`: успешно; пересоздан transfer bundle, 14 файлов. Исходники плагина не редактировались.
- Тесты переменных покрывают многошаговые алиасы, циклы, недоступные переменные, режимы разных коллекций, native mismatch и extension collections на моках. В этом живом файле у каждой коллекции один режим, `valuesByMode` не содержит алиасов на другие переменные. Их сложные цепочки, переключение light/dark и remote/extension-сценарии в Figma пока не подтверждены. Привязка узла к переменной радиуса подтверждена отдельно.
- `strokeTopWeight`, `strokeRightWeight`, `strokeBottomWeight`, `strokeLeftWeight` по-прежнему отсутствуют в списке сериализации. Асимметричные границы не покрыты.
- Mixed typography, сложные эффекты и операции записи этим живым аудитом не проверялись. Figma и реализация Button не менялись; визуальная приёмка не назначалась.

Перед полным переносом light Button требуется устранить ошибки чтения и заново проверить его схему. Для dark Button подтверждены схема, связи радиуса, геометрия и типографика проверенного подробного узла; это не утверждение о передаче всех возможных свойств Figma.

## Полнота и оставшиеся ограничения

Проверена действующая выгрузка на кнопках, а не все возможные типы узлов и свойства Figma.
Отдельно прочитан список DESIGN_PROPERTIES в E:/Codex/figma mcp plugin/src/plugin/read.ts.

- Там пока отсутствуют boundVariables уровня узла и explicitVariableModes/resolvedVariableModes.
- Связи boundVariables могут возвращаться внутри paint/componentProperty и textSegments, но это не заменяет чтение переменных: инструмента коллекций, значений, алиасов и режимов нет. Реальный непустой alias этим аудитом не проверен.
- componentPropertyDefinitions и variantProperties не включены в список; свойства экземпляров componentProperties уже возвращаются. Имена вариантов прочитаны, но полная схема свойств component set не получена.
- Не включены strokeTopWeight/strokeRightWeight/strokeBottomWeight/strokeLeftWeight; асимметричные границы этим аудитом не проверены.
- Тесты mixed styles и сложных effects на реальных узлах не выполнялись; наличие поддержки в исходнике не выдаётся за проверку этих сценариев.
- Дерево ограничено глубиной и числом узлов; предупреждения надо читать и закрывать отдельными запросами. Увеличение depth не добавляет отсутствующие в DESIGN_PROPERTIES поля.

Вывод: прежняя проблема отсутствующих радиусов исправлена; для проверенной геометрии и типографики Button данные теперь достаточны. Утверждение «передаются все значения Figma» пока не подтверждено.
